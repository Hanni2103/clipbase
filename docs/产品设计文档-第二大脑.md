# Clipbase 产品设计文档（第二大脑版）

> 从「跨平台收藏工具」到「个人第二大脑」的完整设计。
> 本文档是后续所有开发的唯一依据（北极星），所有功能、数据模型、接口以本文为准。

---

## 0. 一句话定位

> **把你看过的，变成你的。**

不承诺「收藏」，承诺「转化」——从信息到知识、从别人的到自己的。

---

## 1. 核心命题

收藏工具的共同宿命是同一句话：**用户收藏了，但永远不回来。**

根因：收藏的那一刻，用户心理上是「这事我记下了，可以放下了」。所有工具都满足了这份「放下」，于是收藏越多、负担越重，变成一座再也不进的仓库。

**因此产品不是「存储系统」，是「消化系统」。**

- 记事本存的是**信息**（整块文字，会过时、会遗忘）；
- 这个产品存的是**意图、场景、和用户自己**（为什么存、什么时候用、后来变成了我的什么）。

这两者决定了它和记事本的本质差别：记事本**被动**，这个产品**主动**——让内容在「恰好需要它的那个时刻」出现在用户面前。

---

## 2. 产品分层（六层飞轮）

```
收集 → 精炼 → 组织 → 消化 → 创造 → 沉淀
 一键    原子化   场景+   做减法+   成文+   护城河
 分享    卡片     搜索    唤醒      分享    (价值累积)
```

| 层 | 是什么 | 壁垒 | 现状 |
|---|---|---|---|
| 收集 | 一键分享进来 | 无 | ✅ 已做完 |
| 精炼 | AI 拆解成原子卡片 | 中 | ❌ 待做（冷启动刚需） |
| 组织 | 场景化 + 语义搜索 | 中 | ❌ 待做 |
| 消化 | 做减法 + 主动唤醒 | 高 | ❌ 待做 |
| 创造 | 一键成文 + 分享 | 高 | ❌ 待做 |
| 沉淀 | 价值累积形成护城河 | 最高 | 自然发生 |

---

## 3. 核心概念：原子卡片（Atomic Card）

**判断：收藏的基本单位不是「文章/视频」，是「原子卡片」。**

用户收藏的，从来不是那篇 2000 字的文章或 3 分钟的视频，而是其中打动他的一个**切片**——一个观点、一个步骤、一个数据、一句金句。

### 3.1 原子类型

| 类型 | 字段值 | 例子 |
|---|---|---|
| 要点 | `key_point` | 「黄仁勋说：AI 的护城河是数据飞轮」 |
| 步骤 | `step` | 「空气炸锅 200 度，30 分钟，中间翻一次」 |
| 金句 | `quote` | 「人有两次生命，第二次始于意识到只有一次」 |
| 数据/事实 | `fact` | 「降准 0.5 个百分点，释放长期资金约 1 万亿」 |

### 3.2 为什么这是关键

- 回看时用户看的是**卡片**，不是重读原文（点卡片才跳回原文）；
- 搜索命中「卡片」比命中「整篇」精准 10 倍；
- 主题聚合、场景、一键成文，拼的都是**原子**，不是原文；
- 这是「回看成本趋近于零」的真正实现方式。

## 4. 功能设计与实现

> 每个功能给出：定位、实现方案、数据模型、接口、关键判断。

### 4.1 一键分享（✅ 已实现）

- 用户在任何 App 点「分享」→ 选 Clipbase → 完成，零手动输入。
- 后端识别平台（域名路由）→ 提取文本（网页/公众号/小红书 meta / 抖音文案兜底 / 图片 OCR）→ AI 分类打标。
- 已实现，保持不变，作为收集层的底座。

### 4.2 AI 精炼 → 原子卡片（冷启动刚需，最高优先级）

**判断：这不是后续优化，是第一版就必须有的功能。** 因为如果前 3 条收藏不能让用户「哇一下」，他就不会攒到第 30 条，所有高级功能（聚合/唤醒）都无从谈起。

**实现**：
1. 提取到文本后，除分类外，额外调一次 LLM，产出原子卡片（结构化输出）：
```json
{
  "atoms": [
    {"type": "key_point", "content": "..."},
    {"type": "step", "content": "..."},
    {"type": "quote", "content": "..."}
  ]
}
```
2. 客户端收藏条目展示为「一张卡片 = 标题 + 3~5 个原子」，而不是链接+标签。
3. 每个原子可单独点「跳回原文对应位置」（第一版简化为跳回原文）。

**数据模型**：新增 `atoms` 表（见 §5）。

**冷启动锚点**：用户第一次分享，3 秒后得到的不是「链接+标签」，而是「一句话要点 + 可执行步骤 + 一句金句」。这就是「比我收藏到抖音强多了」的哇点。

### 4.3 语义搜索（最核心的回看能力）

**判断：这是 AI 在这个产品里最不可替代的价值。** 用户真实搜索是「我记得收藏过一个教加字幕的，忘了是抖音还是B站、忘了标题」——只有向量检索能做到。

**实现**：
1. 用 pgvector 存储 `embedding`（见 §6）。
2. 对每个原子的内容 + 标题生成向量，入库。
3. 搜索流程：查询词 → 向量化 → 余弦相似度 Top-K → 返回命中的**原子卡片**（不是整篇文章）。
4. 混合检索：向量（语义）+ 关键词（标题/标签 LIKE），两者加权合并。

**接口**：
```
GET /api/search?user_id=&q=自然语言查询
→ { results: [{ atom, item, similarity }] }
```

### 4.4 场景化组织（取代「死文件夹」）

**判断：用户回看是按「用途和时机」，不是按「主题」。** 主题标签（美食/科技）是用户脑子里最不关心的一层。场景是「活的、有时间性的、用完即焚的」。

**实现**：
- 场景是一等实体（`scenes` 表），用户可手动建，AI 也可自动建议。
- 例：「我下个月去日本」「正在学做饭」「准备面试」。
- 场景可设 `auto_expire`（到期自动归档，不再打扰）。

**AI 自动建议**：当某主题（如「空气炸锅」）连续收藏 N=5 条时，推送：「你最近收藏了 5 条空气炸锅相关，要不要建个『空气炸锅』场景？」——**零成本触发组织**。

**与现有分类的关系**（判断）：保留 10 类主题分类作为**次级筛选**（已实现、成本低、用于浏览），但**场景是第一组织维度**。二者不冲突，分类是「它是什么」，场景是「我拿它干什么」。

**接口**：
```
POST /api/scenes           创建场景
GET  /api/scenes           场景列表
POST /api/items/:id/scene  把条目移入场景
POST /api/scenes/:id/archive  归档场景
```

### 4.5 相似内容提醒（枢纽功能）

**判断：这不是「去重」，是「照镜子」——让用户看见自己的行为模式。** 它把「去重」「场景」「做减法」「唤醒」四件事用一次交互串起来。

**三级判定（关键判断：绝不能一把尺子）**：

| 级别 | 判定 | 阈值 | 提醒 |
|---|---|---|---|
| ① 完全相同 | 内容哈希一致 | hash 相等 | 「这条你已经存过了」 |
| ② 高度相似 | 语义向量余弦相似度 | > 0.9 | 「你存过几乎一样的内容」 |
| ③ 主题相关 | 语义相似度 | > 0.75 | 「你收藏过 N 条关于『X』的」 |

**触发时机（判断：不在分享瞬间，用通知回送）**：
- 分享扩展是瞬时的（用户点完就关），相似度计算需 2~3 秒，来不及。
- 改为：分享后几秒内用**本地通知/角标**回送：「你收藏过 7 条关于空气炸锅的内容，要回顾吗？」
- 好处：不打断收藏动作，又抓住「刚存完、注意力还在」的窗口。

**三个动作**（每次提醒都给，都是价值）：
| 动作 | 价值 |
|---|---|
| 回顾 | 做减法（可能这次不用存了） |
| 建专题 | 场景化的零成本入口 |
| 仍要存 | 记录信号 → 训练系统（以后这类不再误判） |

**文案模板**：
> 「你之前收藏过 7 条关于『空气炸锅』的内容，其中 3 条是菜谱。这次要不要先看看之前的，还是这条有不一样的东西？」

**红线**：阈值保守（宁可不提醒不乱提醒）；一键「这类别再提醒我」；同主题一天最多一次；新用户前 N 条不提醒（冷启动先建立信任）。

**数据模型**：`content_hash`、`embedding`、`dedup_actions`、`user_prefs.muted_topics`（见 §5）。

**接口**：ingest 响应新增：
```json
{ "item_id": "...", "status": "pending", "similar": [{"id":"...","title":"...","similarity":0.82}] }
```

### 4.6 收藏动机 3 秒追问（Tier 2）

**判断：抓住「收藏瞬间」的黄金 3 秒——这是用户唯一还愿意为这条内容花 3 秒的机会。** 这个「动机」比任何标签都值钱，决定以后**在什么时机、用什么方式**把内容递回。

**实现**：分享完成后，弹一次性轻追问（非表单）：
> 「为什么存这条？」→ AI 预填 3 个动机选项 + 空输入框

动机枚举（`intent`）：
| 值 | 含义 | 决定召回方式 |
|---|---|---|
| `do_it` | 照着做 | 时机唤醒（周末推菜谱） |
| `insight` | 觉得有道理 | 定期浮现（间隔重复） |
| `material` | 写作/创作素材 | 场景关联（创作时浮出） |
| `inspiration` | 灵感 | 场景关联 |
| `fun` | 娱乐 | 场景化刷（放松时） |

### 4.7 主动唤醒 + 半衰期（Tier 2）

**判断：主动唤醒是「内容来找你，而不是你去找内容」——这是「管理」的质变。** 但它是双刃剑，红线是「精准 > 频繁」。

**半衰期机制（判断，按内容类型预设）**：
| 类型 | half_life | 说明 |
|---|---|---|
| 资讯 | 3 天 | 快速衰减，14 天后自动归档 |
| 方法/教程 | 60 天 | 长效 |
| 观点/金句 | 180 天 | 常青 |
| 灵感/素材 | 30 天 | 中等 |
| 娱乐 | 7 天 | 快速过气 |

**召回得分**：`recall_score = base × 0.5^(已过天数 / half_life)`，按分排序投喂。

**召回通道**：
1. 桌面小组件 / 锁屏（内容出现在用户日常动线，而非逼他进 App）；
2. 推送通知（可关闭、可解释、有节制）。

**克制红线**：每次打扰 1 秒内可「别再推这个」；宁可一周只推 3 条推对了，也不要每天推 10 条惹人烦。

### 4.8 做减法 / 生命周期（Tier 2）

**判断：收藏工具最大的敌人是「囤积焦虑」。真正稀缺的功能是「帮你放下」。**

**实现**：
1. `digest_state` 状态机：`unread → read → digested → internalized`。
2. AI 主动说：
   - 「这条资讯已过时，建议归档」（基于 half_life）；
   - 「这条你已回看 5 次、消化透了，可以封存了」。
3. 列表默认只显示「未消化」，已消化内容降权到「已归档」区。

### 4.9 一键成文（Tier 3，产品飞轮）

**判断：收藏的终极价值不是「存着」，是「输出」。** 让用户从「收集者」变成「创作者」——人会离开工具，但不会离开自己正在塑造的作品。

**实现**：用户选一个场景/主题 → AI 把该主题下的原子卡片消化重组 → 生成一篇**署用户名的、属于他的指南**（不是简单拼贴）。

- 「一键成文」：20 条小红书运营收藏 → 一篇《我的小红书运营心得》。
- 「周报」：每周自动生成「你上周学到的 3 件事」，一键分享。

**飞轮**：收藏 → 消化 → 成文 → 分享 → 别人来用 → 更多收藏。

### 4.10 情绪价值（Tier 3）

**判断：工具留不住人，仪式感可以。** 给「回来」和「分享」的理由。

- 每周日：「你这周收藏了 17 条，其中 3 条值得再看一遍」。
- 年底：「你今年通过 Clipbase 学到了 XX」（年度回顾，可分享）。

## 5. 数据模型（完整 schema）

> 在现有 `items` 表基础上扩展。新增字段和表用 ⭐ 标注。

```sql
-- ⭐ 收藏条目（扩展后）
CREATE TABLE items (
  id            TEXT PRIMARY KEY,
  user_id       TEXT NOT NULL,
  source_platform TEXT NOT NULL,
  original_url  TEXT,
  title         TEXT,
  raw_text      TEXT,
  content_hash  TEXT,                    -- ⭐ 精确去重（URL/文本哈希）
  embedding     vector(1024),            -- ⭐ 语义向量（pgvector）
  category      TEXT,                    -- 主题分类（次级筛选，保留）
  tags          JSONB DEFAULT '[]',
  summary       TEXT,
  confidence    REAL,
  intent        TEXT,                    -- ⭐ 收藏动机：do_it/insight/material/inspiration/fun
  scene_id      TEXT,                    -- ⭐ 所属场景
  half_life     INTEGER,                 -- ⭐ 半衰期（天），按类型预设
  digest_state  TEXT DEFAULT 'unread',   -- ⭐ unread/read/digested/internalized
  recall_score  REAL DEFAULT 1.0,        -- ⭐ 召回得分（随时间衰减）
  last_recalled_at TIMESTAMPTZ,          -- ⭐ 上次召回时间
  cover_url     TEXT,
  status        TEXT DEFAULT 'pending',
  error_msg     TEXT,
  created_at    TIMESTAMPTZ DEFAULT now(),
  updated_at    TIMESTAMPTZ DEFAULT now()
);

-- ⭐ 原子卡片
CREATE TABLE atoms (
  id      TEXT PRIMARY KEY,
  item_id TEXT NOT NULL REFERENCES items(id),
  type    TEXT NOT NULL,       -- key_point/step/quote/fact
  content TEXT NOT NULL,
  sort    INTEGER DEFAULT 0,
  embedding vector(1024)       -- 原子级向量（语义搜索命中的是原子）
);

-- ⭐ 场景
CREATE TABLE scenes (
  id            TEXT PRIMARY KEY,
  user_id       TEXT NOT NULL,
  name          TEXT NOT NULL,
  emoji         TEXT,
  status        TEXT DEFAULT 'active',   -- active/archived
  auto_expire_at TIMESTAMPTZ,            -- 可选：到期自动归档
  created_at    TIMESTAMPTZ DEFAULT now()
);

-- ⭐ 相似提醒动作记录（喂给系统学习）
CREATE TABLE dedup_actions (
  id            TEXT PRIMARY KEY,
  user_id       TEXT NOT NULL,
  item_id       TEXT NOT NULL,
  similar_item_id TEXT NOT NULL,
  similarity    REAL,
  action        TEXT NOT NULL,           -- review/create_scene/keep/mute
  created_at    TIMESTAMPTZ DEFAULT now()
);

-- ⭐ 用户偏好
CREATE TABLE user_prefs (
  user_id       TEXT PRIMARY KEY,
  muted_topics  JSONB DEFAULT '[]',      -- 「这类别再提醒」的黑名单
  remind_frequency TEXT DEFAULT 'low',   -- low/medium/high
  timezone      TEXT DEFAULT 'Asia/Shanghai'
);
```

## 6. 技术架构

```
[客户端 iOS/Android]
   │ 分享 / 浏览 / 搜索 / 场景
   ▼
[后端 API]  ingest / items / search / scenes / atoms
   │
   ├─ 提取器（网页/公众号/小红书/抖音文案/图片OCR）
   ├─ 大模型：分类 + 精炼(原子化) + 动机预填 + 成文
   ├─ Embedding 模型：向量化（语义搜索 + 相似检测）
   ├─ pgvector：向量存储 + 余弦相似度检索
   └─ PostgreSQL：结构化数据
   │
[通知/唤醒]  推送 + 桌面小组件（Tier 2+）
```

**关键判断**：
1. **向量检索用 pgvector**（PostgreSQL 扩展，与现有关系数据同库，免额外组件）。当前用 SQLite，M3 迁移到 PostgreSQL + pgvector。
2. **Embedding 模型**：复用现有 OpenAI 兼容接口的 embedding 端点（豆包 `doubao-embedding-large-text` 等），维度可配（默认 1024）。
3. **精炼复用分类同一条 LLM 链路**：一次提取，并行产出「分类 + 原子卡片 + 动机预填」，省 token。
4. **相似检测复用向量基础设施**：先做「相似提醒」，再做「全文搜索」，同一套 embedding。

## 8. 商业模式（不伤害体验）

| 免费（基本盘） | 付费（更省心） |
|---|---|
| 无限收藏、搜索、场景、AI 精炼 | 无限 AI 额度 |
| （免费必须足够好，好到用户离不开） | 高级主动唤醒 |
| | 一键成文 |

**判断：基本盘永远免费。** 因为免费用户产生的使用习惯数据，才是主动投喂和护城河的燃料。

---

## 9. 克制原则（红线）

1. **主动唤醒是双刃剑**：精准 > 频繁；每次打扰 1 秒内可「别再推这个」。
2. **相似提醒绝不 judge**：永远不说「你怎么又存了」，只陈述事实 + 给选择。
3. **做减法 > 做加法**：帮用户放下，比帮用户存更多稀缺。
4. **彻底开放导出**：护城河靠「价值沉淀」，不靠「数据绑架」。用户随时能走，但因为价值舍不得走。
5. **阈值保守**：误报一次，用户就关掉整个功能。

---

## 10. 冷启动与信任

- **冷启动锚点**：单条收藏就有即时增值（AI 精炼），不依赖规模效应。
- **信任是产品设计**：数据本地优先、云端加密、一键导出（Markdown/JSON）、隐私叙事理直气壮（「你的数据属于你」）。
